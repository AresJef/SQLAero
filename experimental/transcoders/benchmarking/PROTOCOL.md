# Load-controlled comparison protocol

Version: `sqlaero-load-ab-v1-draft`. This is preparation, not a timing result. The supplied cyTimes protocol and implementation must be reconciled before freezing v1. No machine probes or performance measurements run on import. Real OS adapters, persistent evidence storage and the full benchmark orchestrator remain to integrate.

Use the frozen old release, Cython and installed Rust wheel. Record source and artifact hashes, compiler flags, Python and dependency versions, architecture, workload seed and input shape. Dispatch comparisons must share handlers and include type-ID acquisition costs. Keep dispatch-only and end-to-end runs separate; preserve exact-type/subclass and trusted-hook semantics.

The caller must explicitly provide CPU busy, runnable work per CPU and memory-pressure thresholds, sampling interval, minimum sample count, continuous stable-window duration and maximum waiting budget. Record whether CPU normalization uses logical or physical CPUs and the OS source and units for every metric. A single low load-average observation cannot establish readiness. Missing required signals block a qualified run; never silently replace them with weaker metrics. No project termination or system-setting changes are allowed.

Before each block, require a continuous multi-sample stable window; any threshold breach resets it. Retain every wait observation and timeout. Warm each candidate using identical declared iteration/input rules, retain warmup records separately, then regain stability before timed work. For two candidates use complete AB/BA cycles; for old/Cython/Rust use complete six-permutation cycles. Incomplete cycles must be labeled incomplete. Declare paired repeat counts and stopping rules before execution.

Observe load before, during and after every measurement, including a declared post-run guard window. Native calls that cannot invoke a cooperative sampling hook require a supported separate sampler. Missing during-run observations make a sample ineligible. Capture every result, exception, wait and interference event with block/candidate/order/timestamps. Do not silently delete slow samples or outliers. If interference invalidates a paired block, retain all its measurements, mark the reason and record any replacement as a new block rather than overwriting evidence.

Report raw timings and qualified paired comparisons together with failure/interference counts, wait duration, dispersion and uncertainty. Compute paired ratios within blocks and interval estimates by resampling complete paired blocks; do not treat inner loop iterations as independent observations. Include median and relevant quantiles and disclose incomplete blocks. Choose repetition counts based on declared precision goals, not a favorable winner. Retain contaminated observations in the artifact even when excluding them from qualified estimates.

Never pool distinct protocol versions, threshold policies, workload definitions or incompatible artifacts. Record the complete effective configuration and its digest alongside the protocol version. Any unavailable metric or incomplete observation limits the resulting claim explicitly. Heavy timing waits for an exclusive window free of cyTimes performance work.

`protocol.py` supplies injected stability, balanced-order and interference-recording primitives. Six mock tests verify continuous-window resets, unavailable-signal timeout, AB/BA and three-engine order balance, retained errors/interference, version separation, and rejection of nonfinite load policy. These tests do not validate OS probes or measure performance.
