# Independent Cython experimental kernel

Build from this directory with `/Users/jef/ResilioSync/code/Serializor/.venv/bin/python setup.py build_ext --inplace`, then run `python test_kernel.py`. The existing interpreter supplies CPython 3.13.3, Cython 3.0.12, NumPy/pandas; no files in that environment are modified. `build.log` records the latest isolated compilation.

`sqlaero_cython_kernel.pyx` owns SQL scalar/container serialization, MySQL text decoding, and JSON recursive writer/parser. It never imports or calls an old transcoder or external JSON serializer. Python numeric conversion/formatting, codec and checked datetime object APIs are dependencies. NumPy indexing is object-level and handles strides, endian and alignment without direct pointer dereference. Pandas DataFrames traverse each column before joining rows, preserving native dtype. Date/timedelta tick conversion uses arbitrary-precision integers, including average-calendar month/year duration constants. All callbacks retain the GIL; containers are snapshotted before callbacks.

Register bridge/expression classes using `configure_types(objstr=(...), rawtext=(...), sqlfunction=(...), sqlinterval=(...))`. ObjStr subclasses always call overridden `str`; expressions use public `value`, `args`, `expr`, `syntax()` properties. Public sqlaero error classes are imported when available; documented standalone fallback classes permit isolated import without the production package. `json.dumps/loads` and top-level `dumps/loads` expose the same owned algorithms.

Supported scope includes Python numeric/string/binary/Decimal/calendar types, struct_time, nested standard containers/views, NumPy scalar/record and 1D/2D arrays, pandas date/duration subclasses/Series/Index/DataFrame, and registered SQL hooks. JSON supports native trees, finite/nonfinite floats (nonfinite -> null), bounded 64-bit integers, dataclass, UUID, Enum, datetime/date/time and suitable contiguous native-endian NumPy arrays. Bytes/Decimal/set/custom objects are rejected for JSON. JSON ndarray exotic layouts are explicitly rejected; SQL ndarray exotic layouts are handled safely.

Safety decisions: integer decode is fully consumed and limited to signed-min/unsigned-max 64-bit range; floats accept complete decimal/exponent grammar; nonfinite parsed results reject; invalid calendar text falls back; JSON rejects controls, malformed UTF-8, lone surrogates, overflow and trailing text. Cycles and nesting beyond 128 reject. NaT SQL datetime/duration -> NULL. No raw pointer arithmetic, unchecked C overflow or buffer borrowing exists in this implementation.

Remaining acceptance work: exhaustive numeric byte parity and explicit subclass manifest; mixed nesting uses structural rules; JSON UTF-8 fragments and escaped string sizes are checked before accumulation; whole-document Python/native memory accounting remains open. JSON ndarray layout/dtype rejection policy needs wider frozen-orjson vectors. Numeric formatters use Python/NumPy numeric APIs rather than a dedicated shortest-decimal C writer, so throughput is unmeasured. A small isolated ASan+UBSan suite has passed; broader sanitizer corpora/fuzz and exhaustive frozen-baseline differential checks remain required. This is a functional experimental implementation, not a production-ready replacement or performance claim.
