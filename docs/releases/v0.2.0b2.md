# SQLAero 0.2.0b2

This Beta extends the shared Rust sync implementation to eight native platform
targets and improves common buffered-result materialization. It retains the
0.2.0b1 SQL, precision, error, transaction and TLS contracts. It introduces no
new Escape input types or implicit reconnect/replay behavior.

## Distribution targets

Every row covers ordinary GIL-enabled CPython 3.12, 3.13, 3.14 and 3.15 with
its own native ABI wheel.

| Operating system and CPU | Wheel baseline |
| --- | --- |
| macOS arm64 | macosx_11_0_arm64 |
| macOS Intel x86_64 | macosx_11_0_x86_64 |
| Windows x86_64 | win_amd64 |
| Windows ARM64 | win_arm64 |
| Linux glibc x86_64 | manylinux_2_28_x86_64 |
| Linux glibc aarch64 | manylinux_2_28_aarch64 |
| Linux musl x86_64 | musllinux_1_2_x86_64 |
| Linux musl aarch64 | musllinux_1_2_aarch64 |

The release gate requires 32 original wheel installations, 32 independent
rebuilds/installations of one canonical sdist, and full applicable tests in
each environment. Only the 32 tested original wheels and single sdist are
published. Another 32 jobs download the exact version from official PyPI,
verify the release-manifest hash and installed native bytes, and repeat the
complete Python integration suite. Missing database prerequisites cannot be
treated as passing skipped tests.

Linux runs its installation tests in the pinned native glibc or musl image,
including both real MySQL lines, TLS, Unix sockets, interruption and explicit
Rust integration tests. Test administration uses a shared private fixture
boundary; Docker is not a SQLAero runtime dependency. Windows ARM64 loads an
ARM64 interpreter and extension; the separate MySQL server process may be x64.

The macOS 11.0 and Linux libc tags express compatibility build targets. They
do not imply runtime coverage of every earlier OS or libc patch release.
Actual macOS runners are macOS 26 arm64 and macOS 15 Intel; Windows runners
are Server 2022 x86_64 and Windows 11 ARM64. Async and free-threaded Python
remain excluded. Windows supports TCP and retains its explicit Unix-socket
rejection without silently selecting another transport. Named Pipes remain
outside the supported feature set.

## Buffered result changes and safety

Fetches share one bounded field/byte progress counter instead of restarting
the same signal check at each short row. Entry, exit, row and long-value
decoder checkpoints remain. Final tuples stay hidden from GC until their
slots are initialized; signal and conversion errors preserve the original
exception and leave the fetch position unchanged.

UTF-8, ASCII and byte-valued text reuse CPython's documented native Unicode
constructor contract without repeating a dynamic type check on its result.
Original allocation/decoding errors and strict/surrogateescape behavior are
preserved. Decimal scale, finite-number rules, date recovery and JSON bounded
work/interruption checks are unchanged.

## Performance evidence

Formal comparisons run on the macOS development host against the adopted
0.2.0b1 runtime and a separately identified historical reference. They keep
normal GC enabled, all valid slow observations and complete paired process
clusters. The final report distinguishes new improvements from remaining
historical costs; no universal gain over the alpha or experimental Escape
implementation is claimed. Cloud runners use only fixed short diagnostic
batches, without statistical performance gates.

## Recovery

Keep the previous environment or lock file before upgrading. Roll back by
recreating that environment instead of loading multiple native versions into
one interpreter. Existing tags and PyPI files remain unchanged. A local
rollback does not remove an already published distribution.
