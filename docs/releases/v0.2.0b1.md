# SQLAero 0.2.0b1

This Beta carries the reviewed Rust sync repairs forward and validates the same
source across four native platforms. The public synchronous client and its
supported input types retain their established contracts.

## Distribution targets

- Regular-GIL CPython 3.12, 3.13, 3.14 and 3.15.
- macOS arm64 and x86_64, Windows x86_64, and glibc Linux x86_64.
- Sixteen native wheels and one canonical source distribution.
- Dedicated MySQL 8.4 and 9.7 instances for installed-package integration tests.

Each original wheel is installed into its job's isolated environment and checked
against its exact native member hash before the applicable test suite runs.
The single source archive is independently unpacked, rebuilt and installed into
another environment in every combination. Only the original 16 validated wheels
and canonical sdist are published. After publication, all 16 combinations obtain
the exact version from official PyPI, compare file and native hashes, and repeat
the applicable functional tests. Source-rebuilt wheels are verification artifacts,
not additional published distributions.

The macOS 11.0 and manylinux_2_28 tags describe build compatibility targets. The
actual native runner baselines are macOS 26 arm64, macOS 15 Intel, Windows Server
2022 and Ubuntu 24.04. These results do not cover every earlier OS version,
musl Linux, other CPU architectures, free-threaded Python or async connections.
Windows supports TCP; an explicit Unix-socket request raises the established
unsupported-capability error and never silently switches to TCP.

## Safety and correctness

The Beta includes the completed post-alpha audit repairs: deadline-specific error
codes, TLS material and trust validation, confirmed execution and transaction
facts, maintained client/server error mappings, original exception propagation,
and interruptible bounded-work JSON materialization. A failed fetch keeps its
original position and releases temporary output. Cleanup does not replace the
primary error or invent a confirmed transaction outcome.

Non-Apple CA verification is implemented at the transport boundary using the
selected public Rust/OS facilities. Explicit trust anchors replace system roots;
VERIFY_CA omits hostname matching while retaining certificate-chain, purpose and
time validation. VERIFY_IDENTITY additionally verifies the peer identity. TLS
does not fall back to an unverified connection after a verification error.

No new Escape input types or implicit reconnect/replay behavior are introduced.
The 0.1 Cython API and the frozen experimental implementation remain separate.

## Performance evidence

Formal performance protection belongs to the macOS development host and uses
the adopted local repair artifact as its baseline. The original alpha's timings
and the previously accepted repair costs remain historical evidence, not claims
about the new CI binaries. No universal performance gain over that alpha or the
experimental Escape is claimed.

Cloud runners record only eight fixed diagnostic tasks with five short wall
batches each. Those observations help identify build or order-of-magnitude
problems; they do not supply statistical 1%/5% regression verdicts. Platform,
artifact and final successful workflow timing evidence is recorded separately.

## Recovery

Keep the previous environment or lock file before upgrading. Roll back by
recreating that environment rather than loading different native versions into
the same interpreter. Existing release tags and PyPI files are preserved; a
local rollback does not retract an already published distribution.
