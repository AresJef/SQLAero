# Python 边界类型扩展契约：Escape 与 Decode

状态：已随[实施计划](../tasks/gil-nogil-support/plan.md)获批，作为当前开发依据；实现与验收正在推进，尚不宣称NoGIL已可用。本文说明长期实现规则；具体类型清单、版本、尺寸／深度／工作窗、质量阈值及本次范围仍由对应有效规格决定，不将阶段数字固化为永久架构。

## 1. 共同边界

- **同源同义。** GIL与NoGIL共用一套源码、公共接口和数据语义。成熟公开组件承担运行时差异，必要薄适配集中在绑定／构建边界，不在业务热路径散布平台判断。
- **Rust核心无Python依赖。** Python对象、协议转换、最终Python值／异常只在批准的绑定边界处理；核心使用原生类型、有效切片、拥有者和状态。借用可以被同步消费，但不得把其Python拥有关系藏入核心的存储／异步任务。
- **线程挂接不等于排他。** 调用Python API须attached；NoGIL下Python token不证明独占。不通过unsafe Send／Sync声明、全局锁或强制开启GIL掩盖真实拥有关系。
- **观察语义先确定。** 数值精度、负零、NULL／非有限、时区、编码、容器结构、用户转换、副作用和错误类型由规格决定。错误恢复及可选诊断自身的消息、名称和临时对象构造也必须可失败，不能以诊断失败覆盖主因。性能优化不能偷偷跳过约定语义。
- **边界准备后复用，动态事实仍检查。** 类型／列策略、编码和配置在适当边界准备；长度、NULL、偏移、资源、当前会话上下文及实际拥有关系依赖变化时正确处理，不能以一次校验取消动态安全。
- **测试证明的是具体范围。** 记录源码、解释器、ABI、实际加载路径／哈希、GIL状态、数据和工作边界。静态论证、实测、普通GIL与真实NoGIL分别标明；无失败不能代替充分证据。

## 2. Escape 输入类型的规则断言

| ID | 必须成立的规则 |
| --- | --- |
| E01 | 新Python输入类型的识别、安全读取、必要转换、值语义与行结构适配统一属于Escape；映射到现有Rust契约时，外部执行器不维护额外类型白名单或专用补丁。全新协议／语义另明确必要契约，不伪装成普通类型登记。 |
| E02 | 每个读取明确根／父／当前值的有效拥有者与生命周期。不可变数据优先安全借用，需独立保留才取得拥有引用；可变容器不能借用可能失效的元素指针。 |
| E03 | 调用方在读取期间保持输入及可变嵌套值稳定；库不承诺整批原子快照或发现每次修改。违反约定也不能允许悬空访问、越界或内存损坏。 |
| E04 | 可变字节／存储只在可证明保护的短区段读取，按需取得Rust自有快照。保护内不执行可能释放保护的Python调用、信号处理、detach或不受控最后引用析构；每次保护外工作后重新取得需要的视图。 |
| E05 | list读取保持必要强引用；tuple只在父对象持续保活、元素位置不可变时借用。父容器不可变不代表子对象内容不可变，子适配仍执行自身规则。未来数组／外部存储也必须核实所有权、可变别名和元数据有效性。 |
| E06 | 值同步直接写入当前Rust请求；不创建逐值Python SQL字符串、不默认整批预扫描或通用Value树。必要复制服务于安全和生命周期，不能把所有输入先转成Python中间类型。 |
| E07 | 新增分配与尺寸运算必须可失败、检查溢出并遵循既定限额和错误顺序。不能先为必然超限输入大分配；原生分配失败复用共用错误边界，避免为其消息再次分配或延迟执行String到Python的转换，不以panic／unwrap覆盖原始分配失败。 |
| E08 | 长值、深结构与大批次按累计真实工作保留信号、原操作期限和资源检查；不把每个元素都包attach／detach，也不把整段任意大工作变成不可中断。 |
| E09 | 必要Python转换在边界执行，保持调用次数、可观察副作用和原异常；回调前后的借用／锁有效性分别证明。不得在纯Rust核心回调Python。 |
| E10 | 通用遍历负责行／列／嵌套位置；失败才格式化完整路径和有界摘要。新类型只提供必要位置／安全事实，不建设独立溯源框架，不任意repr或重跑失败转换。摘要失败不覆盖主因。 |
| E11 | 编码上下文来自已确认会话状态；分块／rollover按该事实复用或重编。请求通过拥有的Rust字节交接，网络阶段不使用Python输入或原可变视图。 |
| E12 | 类型扩展同步更新唯一支持说明、annotation／.pyi、英文docstring和正常／边界／失败测试。对当前GIL性能和真实NoGIL并发各给证据，不能只测一个正常值或只证明编译。 |

当前bytearray采用“边界可失败Rust快照→共用bytes writer”，不产生Python bytes；这是当前具体决定。快照分块读取依赖输入稳定性契约，完成后自有数据稳定，不代表无条件单时刻原子快照。

## 3. Decode 结果类型的规则断言

| ID | 必须成立的规则 |
| --- | --- |
| D01 | 新结果类型的列策略、原生解析和最终Python值转换属于Decode。列元信息／解码选项取自该结果的执行时快照，不能读取后来修改的连接配置来改写旧结果。 |
| D02 | 网络／响应解析、Rust结果缓冲与Python构造职责明确；字段切片有贯穿解码、回调、detach和资源交接的拥有者。关闭／换结果不使已交付值或旧元信息失效。 |
| D03 | 直接生成最终Python值和行；不无条件先生成Python中间list／tuple再变换。不为省拷贝暴露可变或失效的Rust缓冲；必要暂存由真实安全／原子性需求证明。 |
| D04 | Python构造仅在attached状态，未发布对象在填充完成前满足其公共API所有权、初始化、GC和并发约束。不能仅以“当前持GIL”或“Rust文件分开”作为NoGIL安全证明。 |
| D05 | 私有tuple／Unicode等原生填充窗口有具体证明：哪些引用存在、是否GC可见、允许哪些API、何处可能回调／阻塞／safepoint、何时完成和发布。允许回调的区段先满足半成品不可被不安全访问的条件；不能把关键窗口禁回调扩大为删除既有信号检查。证明不清先使用可维护安全路线，不以未初始化可见对象换速。 |
| D06 | 所有fallible构造检查NULL／Result并保留原MemoryError及用户控制异常。内容错误、编码错误、资源限额与原信号来源分开；不能统一包装为“数据格式错误”，不能由panic逃逸。 |
| D07 | 长字段、JSON大单值和嵌套内容保留累计工作量中断；按现有来源和规格检查深度／数字／资源限制，不删除必要工作取得速度。 |
| D08 | Decode helper不自行提交Cursor读取位置；全部最终值构建和末次检查成功后，由Reader一次提交。失败保留原位置与约定结果可用性，不以部分返回伪装整次成功。 |
| D09 | 同Cursor冲突和不同Cursor独立本地读取使用既有操作所有权；helper不增加无必要的连接大锁／全局解码锁。不可变Rust结果可共享，Python最终对象和可变缓存按其契约发布。 |
| D10 | 所需类型对象／配置缓存有明确模块或实例拥有者；新类型不偷偷增加进程级Python裸指针缓存。共享缓存构造、失效、GC和首个发布必须由共用状态边界负责。 |
| D11 | 错误位置复用列／行及共用诊断机制，保存原主因和执行事实；不为每类各建链条。错误信息具体、有界、准确，不为诊断再次解析大字段或调用任意用户repr。 |
| D12 | 每种新类型同时验证值与类型、NULL／边界／错误、分配和中断、失败不提交、拥有者／关闭／GC，以及GIL／真实NoGIL使用。先定向后组合验收，有收益的方法再迁往已证明适合的路径。 |

## 4. 两组共同的性能与协作纪律

- 首先区分必须安全修正、可直接复用和可选优化；修改量小不等于影响小，存在普通优化空间也不等于违反规格。
- 每个候选说明当前路径、具体差异、额外／减少的复制、分配、引用、锁和解释器切换；源码可算的操作数可量化，实际纳秒／倍率必须来自有效实测。
- GIL与NoGIL成本分别报告；同一源码的两种解释器结果不能当作纯代码差异，单线程结果不能直接推导多线程线性收益。
- 遵循当前项目有效保护线，固定基准和真实工作量；不串乘历史倍率，不用平均值掩盖场景退步，不按结果挑选样本，不将U改成PASS。
- 文件唯一写入负责人，先约定最小接口再并行实现；公共锁／缓存由其负责人处理。新类型不得顺手改网络、事务、错误语义或调度来让局部测试通过。
- 成功路径不预生成完整诊断；合法对象生命周期保护仍必须保留。无收益抽象、重复转换和整批物化优先撤回，不扩展新的管理框架。

本文不自动授予开发、依赖升级、性能例外或发行权限；具体执行、预算、验证数量和回退见本轮有效计划。实现后应从项目级入口引用本文，避免在多个AGENTS／计划／类型文件复制整套正文。
