### R02：按字段真实格式回退；诊断共用失败分支

位置：core/result/decode.rs 的列 Plan、绑定 output.rs／reader.rs。F17 将 DATE／DATETIME 的原生日期载荷与列名／普通文本 codec 分开，列策略准备后复用；不把所有 TEXT 改为 ASCII，也不扩展任何输入类型。F09 在共同字段转换失败边界追加原始字段的安全有限摘要，保留已有绝对行号、列号、唯一 key、fetch 起点和原错误身份。

验收：两线 MySQL 的零／非法／有效 DATE 与 DATETIME；decode_date_strict 两值；普通 UTF-8 及 utf16／utf16le／ucs2／utf32 结果端设置，确认宽容分支逐字保留实际日期原文、正常日期仍正确。TIME、数字、日期、长 JSON 的失败摘要共用同一机制；按 D11 约定最多 160 个展示字符、控制字符转义及截断明确，不格式化整份字段或任意对象 repr，不重复复制 UnicodeDecodeError 已有完整诊断。首次／后续 fetch、跨批绝对行号、失败位置不推进及临时对象释放必须正确。密码、私钥、完整 SQL 和整批参数不能因该工具被自动记录。

### R03：恢复明确的显式根系统政策

位置：core/transport/tls.rs 的 Policy::Explicit 和现有 verify_system_ca Apple 适配。复用所锁 security-framework 的 SecTrust 能力，将显式证书设为独立 anchors，启用 anchors-only；VERIFY_IDENTITY 使用实际名称政策，VERIFY_CA 保链／用途／时间及适用系统政策而不验名称。继续由 rustls／aws-lc 验握手签名，不自己写证书算法、吊销客户端或系统根管理。

验收：自定义根可通过、错误根拒绝、系统信任不能绕过显式根替换；有名称／无名称、过期／用途／适用政策拒绝；默认系统信任、REQUIRED、DISABLED、TLS1.2／1.3及原客户端材料边界保护。TLS 失败不降级，原总截止在系统验证前后检查。系统调用可能同步阻塞及在线政策的现实限制如实说明，不宣称每次都有在线吊销结论或可瞬时抢占。不修改系统钥匙串；复用项目证书及专用实例。选定公开 API 无法满足契约时，停止该接线并提出最小替代，不以 WebPKI 普通证书通过冒称已满足 OS 政策。

### R04：区分协议阶段和认证要求

位置：core/session/connect.rs、protocol/packets.rs／auth.rs。F10 给既有 ERR 解析器传实际已协商能力；初始 greeting ERR 不凭空要求 SQLSTATE，握手后继续严格协议 4.1。F15 分开 greeting 提示、本库 login 声明和服务端实际认证请求，仍只实现 caching_sha2_password；初始其他提示不等于已证实账号要求其他插件。

验收：规范初始 1040 ERR、后续认证 ERR、截断／损坏 ERR，保真实 code／True／消息；不同初始提示下完成所支持协商、必要 AuthSwitch、fast／full 及最终 OK／ERR；实际不支持插件仍明确拒绝。可用原生离线包片段加既有真实服务器／最小转发验证，注明受控分支与自然服务端行为的区别。保护 nonce、帧序号、可信本地 RSA、秘密及禁止网络自动取钥，不增加其他认证算法。

### R05：用同一实际请求事实收尾，而非补文字

位置：core/session/query.rs／state.rs、绑定 connection.rs 的 drive／DriveFailure、cursor.rs 和 errors.rs。

- F12：从现有 Query 提取当前命令源范围、发送／完整响应／确认事实，再在共用错误边界补诊断。连续确认前缀、当前请求和未尝试后缀分开；源行数、命令数、affected rows 与提交事实不混淆。直接 begin／commit／rollback 与受管理 transaction 使用相同事实基础。
- F13：无完整确认且可能改变会话的退役出口，失效必要可变 SESSION 事实；不能仅关闭传输却继续返回旧 autocommit／timeout 等值。明确未发、正常 close、已确认后本地失败及不可变身份分别处理；不为恢复新增每请求探测或 SQL 全解析。
- F07：本命令执行前的 codec 不自动证明失败 ERR 的真实编码。优先使用确实可靠的响应上下文；无法证实时复用已有 escaped_error_text 和说明 note，无损展示收到的字节，保 code／SQLSTATE／来源。仅凭“能被旧 codec 解码”不能认定编码正确，不猜编码、不加查询、不补造服务器已截断的字节。

验收：两线真实批量前缀成功后超时、完整服务器 ERR、明确发送前失败、COMMIT 丢确认、完整 ACK 后本地失败；诊断覆盖当前范围和事实，公开整体计数遵守未知／保旧结果边界。未确认 SET 后可靠性 getter 拒绝旧缓存；普通关闭可靠值仍可读，旧 Columns／buffered 结果不损坏。普通已知编码 ERR 与“同一命令先改结果编码再 SIGNAL”分别验证：能证明编码时保原文字，未知时字节可无损还原且原因明确。F07 的非 ASCII 可读性限制列入交付，不能称任意场景都能恢复原 Unicode 文本。

### R06：提交后清理必须保确认事实，退役不破坏借用
