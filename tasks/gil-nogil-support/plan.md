## 4. 三个板块的最小实施方案

以下为源码级方案，不是已运行结论。通用错误溯源按既有核心约束复用按需路径；没有把此前尚未单独回答的 E06 标成用户已确认。

### 4.1 Escape

- **E-A 必修：** `input.rs:181` 的 bytearray 主读取及 `:62` 的诊断裸视图依赖 GIL。主路径改为可失败的 Rust 自有快照；取得初始长度、按共用 writer 规则检查尺寸／溢出，再 `try_reserve_exact`。复制分工作块，每次在短对象保护区段重新取得长度和切片；区段内仅原生复制，退出后检查同一期限与信号。完成后复用共用 binary writer。
- 固定 PyO3 的 `bytearray.to_vec()` 虽有 critical section，但内部分配为 infallible `to_vec`；不能直接用它代替本库 MemoryError 契约。不得把 Rust 容量溢出测试冒称真实物理 OOM。
- 分块复制不是任意并发写下的原子快照；同长改写不保证发现，遵循 C04。复制完成后的自有字节稳定。长度变化可按观察到的事实拒绝；不能先拿指针、释放保护再复制。
- 诊断只在保护下复制至多现有 32 字节到栈预览，锁外格式化，或复用已取得的安全事实；不得为摘要再次复制整值，不调用任意 repr／重新执行用户转换。
- **E-B 优化：** `binding.rs:43` 的 list 读取直接复用 PyO3 强引用接口；tuple 即时读取采用安全 borrowed 接口，父对象持续保活。`Rows::at` 返回的行仍可保留强引用，不为省一处引用扩散生命周期重构。
- **E-C 复用：** Rows、环／深度保护、原生 writer、滚动行字节、请求 `Vec<u8>` 交接保留。已有时区／Decimal／信号处理按 E04 核实，无依据不重写。
- **E-D 诊断边界：** 复用 `Visit.path`，成功叶子不新增完整路径字符串；补行／元素取得阶段失败的已知位置。摘要失败不能覆盖主异常。执行事实仍只说“当前请求未发送”，批量已确认前缀由既有执行边界保存。
- **E-E 公共说明：** 将输入稳定性和线程使用规则写入 execute／executemany 英文docstring及.pyi。要求读取期间保持输入稳定；用户最简单的做法是在本次调用返回前不修改输入。区分使用建议和实际拥有边界，不暗中增加整批快照承诺。

量化：n 字节 bytearray 新增 n 字节内容复制及约 n 字节临时存储；现 binary SQL 本体为 `2n+19`，另有 SQL 和命令前缀。原对象、快照和输出同时存在时相关内容约 `4n+19`，不含 capacity slack。每 256 KiB 一块时 K=ceil(n/262144)，临界区次数随 K 增长；这是当前可复用工作窗口，不是永久通用数值。tuple 每个符合条件的借用最多少一对强引用操作，不等同于两条原子指令。GIL 下也按 C03 复制，不暗中改成另一种用户语义。

### 4.2 Decode

- **D-A 早期证明与探针：** 优先保留 `output.rs:15–85` 和 `json.rs` 的直接最终对象路线，按最终固定的 3.14t／3.15t 补丁版本分别核实所有权和 GC 契约。ready tuple 在 New 成功返回至完成填槽之间不运行回调、detach 或阻塞操作；streaming tuple 在 New 成功返回至立即 UnTrack 的窗口禁止这些动作，UnTrack 后保留既有解码、信号检查及可能的 GC，全部槽有效后再 Track。私有 Unicode 保留 progress 回调，但完成前不 hash、不取 UTF-8、不克隆拥有引用或共享对象。安全说明基于 attached、唯一拥有和具体窗口，不以 Python token 代表排他。源码论证与真实 NoGIL GC 压力测试缺一不可，均不表述为已证明没有未知缺陷。
- **D-B 定向修正：** 固定 PyO3 0.29.2 `PyTuple::new` 路径存在 allocation NULL 后 `assume_owned` 的源码级 panic 风险。`output.rs` SET 及 `reader.rs` 宽行／外层使用处改用本项目 fallible ready helper，保留现有 Vec／窄行栈布局。先故障注入核实，不把旧测试全绿当作已覆盖此路径。
- 稳定入口保留 `field`、`tuple_from_ready`、`tuple_from_values`；可新增仅接收已完成拥有引用的 `tuple_from_ready_vec`。reader 接入由状态负责人完成，Decode agent 不抢写 reader。
- **D-C 复用：** 数值／日期／字节／Unicode 公共 fallible API、jiter 的 Rust streaming parser 和现有 checked progress patch；不改未走到的 jiter Python parser／全局 string cache，不通过移除中断提速。
- **D-D 可选优化：** 将现有直接最终 tuple 的方法用于宽行／宽结果，可能省掉每宽行一个引用 Vec、每次 fetch 一个外层 Vec，但会改变 GC transitions。先用宽度 5／8／32 与数值／文本／JSON 混合场景比较；无可靠净收益就保留安全的现布局。

量化：复用直接构造不必新增每字段锁、额外整份文本缓冲或中间 Python 行。safe ready helper 只转移已拥有引用。注释和证明本身不增加运行指令；新增 GC 操作、引用管理及 NoGIL 对象分配成本必须实测，不能预报百分比。

### 4.3 共享状态、缓存与生命周期

- **S-A 复用：** core `CommandLease`／try_lock 立即 Busy，Reader.active 操作 guard，锁外最终对象构建、末次检查后一次提交 position，metadata／Columns 已有二次检查及 Arc 身份，Retry 的局部 active 与锁外等待。
- **S-B 必修：** `errors.rs:279` 的查缓存→锁外 capture→无重检发布可能覆盖中间新增事实。采用局部失效标记：锁内读标记，锁外捕获，再锁内重检，已有胜出缓存则复用，标记未变才发布。所有真实新增诊断事实的记录路径（note、additional、stage 实际改变、native 更新）在修改事实的同一临界区更新标记并 take() 旧缓存；旧缓存及落选候选在 guard 释放后析构。与更新重叠的调用可返回其已完成的不可变候选，但不得缓存旧候选；更新完成后发起的下一读取应反映新增事实，旧已交付快照不变。不为此建立跨项目版本系统。
- **S-C 必修：** `ErrorInfo` 公开延迟 getter 不再用相互竞争的 `borrow_mut` 发布。用独立的一次发布槽：读取→锁外生成→set→返回已发布对象；不在 `get_or_init` 初始化门内执行任意 Python。私有、尚未公开的图构建另作生命周期证明。
- **S-D 必修：** 将实际定位的锁内 Python 分配／错误构造和可能触发 Python 析构的最后引用释放移到锁外。重点为 reader 无结果错误、Cursor 计数转 Python、connection 属性失败、metadata 缓存插入失败以及诊断缓存失效。只移动 native 值／错误描述，不重写正确业务状态机。
- GC 会遍历的引用容器不能盲用 `MutexExt`：持锁重新 attached 可能与 `__traverse__` 形成等待环。若保留局部 std::Mutex，普通访问在 attached 状态取得并释放，不让 detached 任务持有该锁或持锁等待重新附着；临界区仅执行已证明无 Python 回调、safepoint、detach 的 Rust 复制／移动及必要引用递增。Python 对象／异常构造，以及可能触发 Python 析构或弱引用回调的最后引用释放，均移到锁外；`__traverse__` 不 attach、不跳过实际引用边。每把锁按真实调用、GC 和析构关系选择，不批量替换。
- **S-E 必修：** Transaction 的 enter 在 BEGIN 等待时可能与另线程 exit 交错，提前释放 scope。给同一上下文的 enter／exit 复用 Reader 式操作 guard，状态变更前取得执行权，冲突立即 Busy，Drop 释放。连接租约及已定业务／提交／清理主因层级不变。

量化：真实诊断失效增加局部标记更新；稳定 ErrorInfo 缓存命中保持短读取，延迟槽命中可免重复构建。Transaction enter／exit 各增加一次操作取得 CAS 和相应释放；不新增每结果字段锁或连接大锁。以上是操作数，不是已测成本。

### 4.4 主窗口的构建与集成

- 统一 PyO3 0.29.2 与 matching `pyo3-build-config`；确需 crate 内 cfg 时由单一 build.rs 导出，不依赖手写版本字符串散布分支。未审查的 unsafe 不以宏默认支持声明掩盖。
- 最终显式支持声明必须与实际已验收 t 版本一致；开发中与最终导入均核实 `Py_GIL_DISABLED` 及 `sys._is_gil_enabled()`。不使用强制关闭 GIL 绕过不支持的扩展。本轮不支持的 t 版本在构建边界清楚拒绝，不影响普通 3.13。
- `release_artifacts.py` 目前假定 ABI=Python tag；Linux SDK 路径同样写死普通 ABI。只在现入口集中加入 gil／freethreaded 变体，保留准确 Python／ABI／架构／libc 身份，不复制脚本。
- 优先检查固定镜像中现成 t SDK；缺失才采用官方可用 SDK／镜像并冻结身份，记录最低运行库影响。Windows 普通与 t 使用隔离环境／job，避免互相覆盖。
- 原发布 workflow 不触发。使用 CI probe／独立验证 artifact 交付 48 wheel＋1 canonical sdist，开发版本／产物身份明确区别于公开 b2，不覆盖旧包或 tag。

## 5. 多 agent 指挥与滚动集成

| 负责人 | 独占写入范围 | 交接与禁止越界 |
| --- | --- | --- |
| Escape | input.rs、binding.rs；scalar／text／binding／batch 对应测试 | 保持 write、Rows、请求契约；需要 writer 小 helper 时向主窗口提准确改动，不能改 cursor／errors 缓存 |
| Decode | output.rs、json.rs；decode_fields／json 测试 | 保持 field 和 tuple helper；给状态 agent 明确新 helper，不改 reader 或扩展 jiter 未使用路径 |
| 状态 | reader.rs、metadata.rs、errors.rs、errors/diagnostics.rs、connection.rs、cursor.rs、transaction.rs、retry.rs 及对应状态测试（含 test_buffered_reader.py） | 涉及Decode的reader改动仅接入约定helper；Reader自身锁边界、快照和位置协议修正由状态负责人完成。Escape所需cursor文档由其提供文本、状态负责人落地，不双方同时写 |
| 主窗口 | Cargo／build.rs／lib.rs／typing和.pyi／CI／工具／核心Rust必要小helper／计划与最终证据 | 管理公共签名、基线、构建队列、采用及反退化；不让“集成由别人负责”成为遗漏 |

1. 启动前向每名 agent 提供同一 B0、既有决定、扩展契约、文件所有权、当前检查点和预算。明确其不是唯一开发者、不得撤回其他人改动，不自行扩大支持范围。
2. 使用任务隔离工作树／固定源快照。共享依赖缓存按 Cargo 现有锁协调，不复制大套历史 target；构建由主窗口排队，按 ABI 隔离产物，避免同路径覆盖或加载旧扩展。
3. 首轮以“最小安全实现＋原有接口”交接，不等待各自写完所有优化。每次交接只提供 diff／提交、真实运行命令及身份、通过／失败／未测、风险与下一动作。
4. 主窗口审查依赖和影响面后整合，先定向验证形成安全组合 `C_safe`。它与旧 B0 均保留，不把未完成候选装入用户环境。
5. 优化一次一个实测问题。独立路径可并行设计／实现，轻量测量统一排队；有依据的收益通过保护后进入 `C_best`。失效证据只撤回受影响部分。
6. agent 完成后可由主窗口改派其只读审查另一组稳定 diff，仍用 Sol Max，不增加常驻角色。主窗口最终复核所有权、GC、锁顺序、原异常和完整数据流。
7. 冲突先保当前最佳，交换接口／补丁，不靠 reset、批量覆盖或 cherry-pick 不明改动解决。不同候选的测试／性能不拼接为一个最终版本。

## 6. 功能与安全验收

先对每种 t 解释器打通实际安装轮，再做扩展测试；GIL 全绿不能代替 t 分支编译或真实并发。所有预期来自现行规格、C03–C10 和公共 API 契约。

| 组 | 必要覆盖 | 判定 |
| --- | --- | --- |
| 输入 | 现有全部类型／many／itemize／嵌套与回环；bytearray 空／全字节、工作窗前后、限额、复制失败、复制和编码中断 | SQL 字节、异常、期限和当前请求事实正确 |
| 借用／重入 | list 删除／替换、tuple 嵌套可变值、tzinfo／信号重入、正常共享只读输入 | 不悬空、不死锁；违反稳定契约时不承诺原子结果或发现每次修改 |
| 输出 | 窄／宽行、空／多行、各 decode 选项、Unicode 各存储宽度、JSON 大单值／密集转义／嵌套 | 最终类型和值正确，不暴露无效半成品 |
| GC／分配 | 并发 gc.collect／gc.get_objects 与对象构建；Python allocation 故障注入及 Rust fallible reserve 路径 | 原 MemoryError／控制异常，不 panic；失败不提交 fetch 位置，后续按约定可读 |
| 缓存 | 并发冷读、胜出对象复用、增量诊断失效、旧快照不变、弱引用回调／清理重入 | 无 borrow panic、陈旧缓存回写、重复发布身份错误或等待环 |
| 生命周期 | 同连接／同Cursor Busy，不同Cursor本地读取独立，Transaction enter／exit 窗口、close竞争、结果拥有者与GC回收 | 本地状态与已确认执行事实一致，不丢作用域，不自动重放 |
| 回归 | 既有 TLS／认证／编码／绑定／事务／超时／错误目录及retry，类型和英文文档 | 改后安装包适用全量测试通过 |

复用 `_native_signal.py`、隔离子进程、真实 MySQL fixture 和已有 `_testcapi` 入口；先核实钩子在 t 环境确实可用。注入 Python allocator 故障的进程不同时运行并发线程；不得把整个宿主推向物理 OOM。必要钩子缺失时寻找等效最小验证并说明边界，不能直接 skip 后称通过。

NoGIL 验收至少记录构建标志、导入前后及实际关键工作之后的 GIL 状态。测试进程必须真实禁用 GIL；普通构建、t 构建但 GIL 开启、以及 t 构建 GIL 关闭，三者不能混同。已准备结果的本地解码与网络发送的并行范围分开，信号处理遵循 CPython 主线程规则，不承诺 SIGINT 自动取消所有工作线程。

## 7. 性能合同与优化决定

### 7.1 基线和比较对象

- **B0：** 本次开始的 b2 运行时源码，必要时同环境重建并核验；固定至项目结束。
- **C_safe：** 最小双运行时安全组合，不先混入多个可选优化。
- **C_best／C_final：** 安全基础上滚动采用、最终冻结的同一源码。
- GIL 主正式比较沿用现有 macOS／固定 CPython 的 production visitor／Reader／真实MySQL计时边界；B0 与候选使用同补丁解释器、编译参数和机器。默认复用原 cp313 测量入口，实际路径在 P01 冻结。
- 同模块相对当前最佳的增量比较用于决定小改动；最终 B0→C_final 直接配对用于累计保护。只在归因不明时建隔离模块对照，不为所有组合重复全矩阵。
- NoGIL 单线程另以同一新源码的普通 3.14／3.15 与对应 t 解释器比较，报告解释器与代码成本混合边界；不能把跨版本差异归于本库改动。t+GIL-on只作有具体疑点的诊断，不算 NoGIL 验收。

### 7.2 范围、分档与报告

沿用现有 486 场景作为最终必要 GIL 保护，另补确有缺口的 bytearray／宽行／缓存边界场景，冻结 ID 和输入；不新增无关类型、历史版本或第三方库对照。开发候选只跑目标及真实受影响保护，最终组合才完整采集主轮和独立轮。

沿 D12-Q20：可靠收益尚未达到 5% 时，适用保护增量≤1%；可靠达到 5% 时才可用≤5%档位。时间收益 `g=1−t_new/t_ref`，因此证明 5% 收益需要倍率区间下界达到 `1/0.95`，不能误用 1.05。见证场景和适用范围在采样前登记，不从已测胜者事后挑选，不把平台／功能增加当作提速。

最终累计比较仍须说明适用档位及依据。每项报告主／独的绝对时间、配对倍率／区间、耗时增量、纳秒或微秒差；不能把两边际中位数相除冒充配对效应。主／独任一必要可信超线不能被另一轮或总体平均覆盖。无业务频率时不制造综合加权收益。

覆盖、数据质量、统计充分／稳定、性能分别判定，保留 PASS／FAIL／INCONCLUSIVE。旧 B0 已有成本／U 是基线事实，不是新候选豁免。对 bytearray 等必需安全成本有预期也不预先批准未知百分比。

### 7.3 复用测量，不重建工具

使用现 `tools/benchmark.py` 的 prepare／calibrate／run／summarize、固定一次必要预热和原 JSONL 恢复能力。复核上轮最终固定预热合同，复用有效参数，不能把原始默认16次／2ms截断重新当作公平初始化。正式前用最小完整单元验证加载、工作量、GC、配对、保存和读回。

保留正常 GC、必要分配／释放／输出消费、相邻完整 AB／BA、真实进程聚类、95%双侧配对中位效应区间及仍适用的20,000次bootstrap；具体配额和层级在预试后冻结。旧样本不混入；历史数量不自动等于本轮充分，也不无差别升到512周期。不拿旧r5、rsTimes或另一个项目参数替代当前合同。

合格慢值全部保留，无效组补原槽，不按输赢择优重测。复现同因失败时查批长、准备历史、GC、计时边界和实际工具成本。身份／准备语义／统计变化单独保存配置，指定场景完整主／独替换、更差也采用；其余证据只有身份与影响条件有效才复用。

### 7.4 NoGIL 并行效果

用少量代表工作负载测量：独立连接参数编码、独立已缓冲结果解码，以及包含Python业务计算的用户流程。先用1／2／4线程，机器资源允许且确有信息价值再扩展。报告总完成量／墙钟吞吐、延迟、CPU和峰值内存，不拿同连接命令串行场景要求线性加速。

当前 benchmark 是单线程／进程成对计时，不能机械套用“进程CPU≈当前线程CPU”的拒绝规则。确需多线程计时能力时，在现有测试／工具中增加最小固定工作量入口并单独冻结线程协议，不重造测量平台，不以移除必要校验换绿色结果。安全与功能是门槛；没有约定一个适合所有负载的线性提速百分比。

### 7.5 优化与有限恢复

顺序：一项有证据问题→一个小改动→定向正确性→轻量性能→采用／撤回→必要保护。优先减少本轮新增成本，再尝试 tuple 引用、bytearray 分配／复制组织、宽结果暂存和缓存热点。

局部检查点通常20–40分钟，属于自查触发而非自动终止整个项目。没有可靠收益或无新信息就停止同一路线；质量不足先定位，不把 U 当退步或持平。能装入余额且有新证据时可换最小路径，保留原失败。A04已获批准；有因果依据、固定集合和完整成本的准备／参数恢复由主窗口自主决定，不反复请求小额度。超线／必要U按最新C12具体量化、合理尝试后自主作取舍并保留原状态；不改变实际计时工作、统计可信度、质量或保护线，不以子agent建议替代主窗口责任。

### 7.6 必需交付：最终新版本对当前B0的完整GIL性能报告

**报告对象固定。** 当前版本是本轮起点B0（b2运行时源码／核实后的本机产物），新版本是最终C_final。两者均在同一普通GIL解释器、同一补丁、同一macOS机器和构建设置下测试，明确运行时GIL实际开启。不是和SQLCyCli官方、V23、orjson或某个中间候选比较；不使用旧成绩充当本轮配对成员。

**每个场景都应有可读结论。** 按Escape、Decode／结果组装、共享状态／缓存和真实连接／执行分组，再按类型、模式和尺寸排列；没有适用测量项的接口说明原因，不虚构模块总收益。每项至少列：稳定ID与输入规模、主／独B0和C_final绝对时间、绝对差、配对速度倍率与95%区间、耗时增量及区间、覆盖／质量／统计状态、性能方向、适用保护线与通过状态、已知代价或限制。

速度倍率采用 `T_B0/T_C_final` 的配对估计：大于1表示新版更快；报告直接写明“新版快X倍”或“旧版快Y倍”，并同时给出耗时百分比，避免倍率方向混淆。不能用两个边际中位数简单相除替代正式配对效应。收益方向与保护结论分列：“方向未明确但保护线通过”不等于“统计未明无法判断保护”；没有可信差异也不等于速度完全相同。
