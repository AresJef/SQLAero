## 3. 六项交付的具体修正与验收

### M01：P1，共用Python分配失败与异常恢复边界

映射：R01＋F1；边界E07／D06／D11，核心约束6／11／14。影响位置为`input.rs`、`config.rs`、`retry.rs`、`errors.rs`和`errors/diagnostics.rs`的已定位实际调用链。

最小方案：

1. 复用`builtin_error`及已有检查NULL／Result的对象构造，把错误消息、关键字字典／键、方法名称、slice、最终字符串、默认float等**实际可达**同构分支收敛为可失败路径。不只处理六个探针入口，还检查它们共享helper的直接调用者，防止相同错误结构在相邻分支残留；不借此扩成全库无界OOM项目。
2. 在从Rust返回Err及FFI恢复异常之间，避免延迟Rust字符串→Python对象的不可失败转换；Python错误实例分配本身失败时保留CPython实际错误。不用`catch_unwind`把panic包装成普通异常。
3. datetime C API采用可失败的冷准备／拥有状态；优先在适当绑定边界准备后复用，而非每个值再import。模块Python导入成功不能当作其C API已准备。若改成模块初始化时准备，测试真实的新初始化入口，不强行保留有问题的旧冷路径；不新增进程级Python裸指针缓存。
4. 默认与显式Retry参数走相同可失败基本构造；不为省分配改变用户可读属性或参数类型。

必须分别覆盖的六个子路径：

| 子路径 | 最小核验及完成标准 |
| --- | --- |
| 已raise异常的实际栈捕获 | 公开`error.error_info`，raised／unraised、冷／缓存、诊断失败后再次可读；原主异常／旧快照不被破坏 |
| 普通无效配置的异常恢复 | 零／负数／过大时长和错误类型；正常值保持原TypeError／ValueError等约定，分配失败正常传播；明确未发网络请求 |
| 冷datetime C API | 隔离新进程中的真实初始化／首个编码入口；普通unsupported object也不能因经过日期类型判断而panic。日期／aware datetime正常编码、UTC检查及原回调继续正确 |
| Retry默认浮点构造 | 默认与显式设置、freelist冷／热；分配失败不是PanicException，不影响后续未注入调用 |
| 公开SQLAeroError非法构造 | 预先准备`SQLAeroError(42)`等真实拒绝调用，捕获预期错误；不能以宿主SIGABRT结束 |
| ErrorInfo traceback／显示 | 正常`traceback`、`str`／`repr`与有实际堆栈的lazy getter；构造失败保留实际错误，无半成品发布或源异常泄漏 |

验证复用Review隔离单次分配故障工具：注入前准备callable和参数，故障点有界、每个子进程有限超时、清理hook；保存解释器／native／实际阶段。不能用同一offset推断所有ABI失败点相同，不能把进程exit0等同产品通过。回归断言最终异常类别、可得时的原对象、未panic／abort及下一正常调用；正常错误与OOM结果分开验证。

性能保护：冷／热诊断、错误码、Retry构造；配置及import准备；所有标量／容器、日期时间和真实连接／fetch。不预报纳秒成本，正常成功路径不额外生成诊断。

### M02：P2，Reader退役清理交接

映射：R02＝F3；`reader.rs:64–70/126–130`及`transaction.rs`强制清理调用；D02／D08／D09、核心6／7／11。

根因是`closed`与`active`两个独立check-then-act导致释放责任丢失。优先采用一个可线性化的局部状态（例如同一原子状态中的active／retired事实和明确的责任转移），或证明等价的短原生同步区段；不是给原两个bool加SeqCst就结束。先写清每条状态转换的线性化点、谁取得唯一清理责任、何时锁外释放，然后替换错误交接结构。

复用当前`ReadData`的Arc拥有者、metadata快照和实际Reservation；退休不取消正在解码的操作，不抹掉已完成输出或原错误。新的操作权、关闭和强制退役均进入同一事实模型，不另加连接全局锁。

必要验证：

- 直接对生产使用的状态辅助逻辑做受控调度／原子单测，覆盖退出先发生、退休先发生、交错及重复关闭；已有Review模型作RED证据，**不能只另写一份永远正确的玩具模型作为GREEN**。
- 公开实际包覆盖：部分`fetchone`／`fetchmany`后保留未读行、并发事务强制清理、正常读到末尾、解码失败／中断、保留关闭Cursor和旧Columns。
- 以已有内存池／Reservation接口核对行存储和额度确实归还，不只看`closed=True`。公开调用验证值／状态，受控原生测试验证最窄交接窗口；二者分别标注，不要求盲压测撞中数纳秒窗口。
- 无重复释放、无UAF、在途Arc有效、无读取位置半提交；同Cursor冲突仍立即Busy，其他Cursor独立本地读取不被全局锁阻断。

性能保护：单行／多行／宽行fetch、关闭与事务退出、网络等待期间独立本地读；报告新增原子／锁操作及实测成本。

### M03：P2，Columns不可变冷缓存并发发布

映射：R03＝F4；`metadata.rs:251–307`、三个`prepared_keys`调用入口；D09／D10和D09-Q23–Q25／D11-Q30。

完成标准：正常只读竞争不再抛内部准备Busy；既定SQL／fetch冲突仍Busy；没有半发布、锁死、资源限额绕过或旧Columns变化。性能保护冷／热元信息、窄／宽结果及fetch路径，不把冷读改善扩报成每行解码收益。

### M05：P2，Retry原数值提取错误传播
